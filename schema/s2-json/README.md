### Why the licence is copied rather than linked

Because Apache-2.0 makes it a condition of redistributing the files at all:

> **4. Redistribution.** You may reproduce and distribute copies of the Work
> … provided that You meet the following conditions:
> **(a)** You must *give* any other recipients of the Work … *a copy of this
> License*.

A link in a README is a pointer, not a copy, and it fails in both directions
that matter. Someone who downloads the `.crate` from crates.io receives the
schemas in the tarball — if the licence is not in there with them, they have
received the Work without its licence. And a URL stops resolving when a
repository is renamed, moved or deleted, while the obligation does not lapse
with it.

It costs about 4 KB compressed, a little over 1% of the published crate.

### About that `[yyyy]` in `LICENSE`

`LICENSE` ends with an `APPENDIX: How to apply the Apache License to your
work`, whose boilerplate reads `Copyright [yyyy] [name of copyright owner]`.
Leave it. That file is **upstream's**, redistributed byte for byte under
Apache-2.0 §4(a); editing it would be editing somebody else's licence, and
`tests/vendoring.rs` fails if anyone does. Upstream's copyright holder is
named above, which is the part that is ours to write.

## Why they are committed rather than fetched

* The crate must build and test **offline**. docs.rs has no network, and
  neither do most CI sandboxes.
* A fetched copy makes the tests mean something different from one day to
  the next, silently, when upstream changes. A committed one makes that a
  reviewable diff.
* This crate's central claim is that its hand-written model is *proven*
  against the official schemas. Shipping them in the published `.crate`
  makes that claim checkable by anyone who downloads it — for about 19 KiB
  compressed, which is the whole cost.

Nothing in `src/` reads them at build time: `src/schema/table.rs` is
*generated* from them, and is a few kilobytes of names and array bounds
rather than three hundred of JSON. They are used by
`tests/model_matches_schema.rs`, which validates every message against them
with a real JSON Schema validator, and by `cargo xtask gen-schema-table`.

To refresh them, clone `s2-json` into `specs/` (gitignored, and it must not
be a shallow clone — the `v0.0.2-beta` tag is read from git history) and run
`cargo xtask vendor-specs`. CI fails if the result differs from what is
committed.
