## S2 Connect

Discovery, pairing, session initiation and the transport are implemented for
both sides. `tests/connect_e2e.rs` pairs this crate's client against this
crate's server over a real TLS connection, which exercises the one thing an
in-memory test cannot: the leaf-certificate fingerprint the challenge response
binds to comes out of a genuine handshake.

| Part | State |

## Not claimed

* **Interoperability results.** Nothing here has been run against another
  implementation in CI yet; when it has, the matrix will live in this file
  and say which revision of which peer it was run against. Pairing this
  crate against itself proves self-consistency, which is not the same thing.
* **Certification.** There is no S2 certification programme, and this
  document is not one.
* **Deciding whether you are a LAN or a WAN endpoint.** `router` serves only
  the authenticated operations, so a WAN endpoint answers `404` on the rest, as
  `S2C` recommends. `lan_router` adds them and *requires* `LocalSubnets`, so the
  unauthenticated operations cannot be exposed without their access control. Which
  one you mount is yours to choose; forgetting the subnet check is not.
